# 硬件与刷写边界

目标开发硬件：M5Stack StackChan K151，CoreS3 / ESP32-S3，16 MB Flash，320×240 触屏。其他 StackChan 改装板、裸 CoreS3 和分区布局不在已验证范围。

## 第一次修改固件

1. 用 USB 数据线连接，确认实际设备型号和端口，读取 Flash 大小与原厂分区表。
2. 保存属于这台设备的完整原厂 Flash 和校验值，并另存一份。备份中可能包含配网和设备资料，不能公开分享。
3. 核对应用分区、NVS 和校准区域后再决定刷写方式。开发设备的微光应用在 `0x10000`，只更新应用，不擦除全 Flash、不覆盖分区或校准。
4. Mac 桥接运行时先 `./weiguang pause` 释放串口，再操作；更新后 `./weiguang resume`。不要让两个串口程序同时占用设备。

本仓库有意不提供未知分区下的自动刷写脚本；`pio run` 只负责生成镜像。不要把 `pio run --target upload` 当作上面步骤的替代。

## 传感与动作

摸头使用 Si12T 传感器，舵机驱动依据原厂只读校准值计算小幅动作，带限位、节流与停止保护。校准信息缺失或读数异常时拒绝动作。它不能让任意舵机／装配方式变得兼容。

不使用“摸下巴”接近触发。机器人麦克风与扬声器保持关闭；可选摄像头仅在显式启用的 USB 本地视觉中使用。任务同步无需 Wi-Fi；语音在 Mac 上使用 AirPods 和原厂云服务，不使用 Codex 订阅。物理头部跟随实验已取消。

## 验证范围

历史开发版本在一台实际 K151 上完成 USB／蓝牙、任务显示、触控、摸头、专注与休息循环测试。v0.46 已部署并检查便签显示、Mac 收起／恢复与设备重启保留；手指长按手感尚无人工确认。Mac 自然重启登录、长时间稳定性、真实断电统计恢复和完整原厂恢复不列为已验收。

诊断串口的打开可能触发 USB_UART_CHIP_RESET。先确认没有正在计时的番茄钟，再进行串口诊断，并等待蓝牙和日期恢复。
